## 1. AUM-IC Philosophy

[AUM-IC](https://github.com/ingcrea/aum-ic) (Arquitectura de Universos Multidimensionales de Ingeniería Creativa — Architecture of Multidimensional Universes of Creative Engineering) is our internal standard for eradicating technical debt and restoring sanity to web development. Software is a fractal consciousness system; therefore, styles must be scalable, modular and respect a logical expansion hierarchy: **Atoms, Molecules, Organisms, Ecosystems and Universes**.

### 1.1. Pragmatism and Framework Liberation

We grew tired of the fragility and coupling generated by tying massive projects to Tailwind utility classes. We built this orchestrator to automate a destructive and precise migration: extract utilities, purge the original framework and generate a standardized CSS ecosystem. The goal is simple: your source code stops being a slave to an external dependency and becomes an immutable, clean, and eternally scalable asset.

### 1.2. JIT Interception (Zero-Bloat Guarantee)

We don't generate CSS by hand or guess styles. Our engine instantiates the native Tailwind `JIT` (Just-In-Time) compiler silently in RAM, injects a virtual DOM, and lets the original algorithm minify the code. Once optimized, we execute a tactical CSS hijack and replace selectors with AUM-IC hashes. The result is pure CSS structurally identical (byte for byte) to the original framework. Zero dead code, zero bloat.

### 1.3. Determinism, Collision Prevention and AI Semantic Naming

Delegating massive class naming to an AI file-by-file causes inconsistencies, CSS collision collapses and an absurd token expenditure. We solve this with the **Titanium Cache** (`aumic-lock.json`) and our deduplication algorithm.

The engine forces a strict 1:1 mapping: if a card (`bg-white shadow-lg p-6 rounded-xl`) repeats 5,000 times in your monorepo, the system compresses it to a single mathematical combination. It is thanks to this unification architecture that we can safely integrate **AI Semantic Naming** (*Ollama, Claude, Codex, DeepSeek, Gemini*). By sending only the deduplicated dictionaries — never the full source code — we guarantee **zero style collisions**, save millions of processing tokens, and shield privacy (Zero-Trust): the company's intellectual property and business logic are never exposed to third-party servers.

### 1.4. Immutability (Zero-Trust)

If the orchestrator is not invoked with the destructive mutation flag (`-m local`), it operates under a state of absolute distrust (Simulation Mode). The engine will never overwrite your components (React, Astro, Python) unless they pass the Pre-Flight validation, verifying filesystem permissions and your Git tree status. We prevent corrupt states before they occur.

### 1.5. Absolute Scalability (Multi-Level Cache)

Processing thousands of files in corporate monorepos demands deterministic speed. The architecture operates under a two-level cache network that destroys bottlenecks:

1. **L1 Cache (DuckDB - Static Oracle):** Via reverse engineering, we pre-compiled and extracted exact CSS equivalents for 26,000+ native utility classes. All this data lives in a super-compressed binary database (`aumic-lexicon.duckdb`) operating under massive columnar compression. It injects CSS values directly in O(1) time with zero processing cost (Zero-Execution). Its universal dictionary nature makes it impervious to architectural changes, supporting everything from legacy ecosystems (v1, v2, v3) to the new Oxide engine (v4).
2. **L2 Cache (Dynamic JIT):** Dynamic injection capability that hijacks the user's own `node_modules/tailwindcss` environment. This fuses the speed of an analytical database with the millimetric precision of the client's local engine, guaranteeing infinite scalability regardless of the underlying framework version.

### 1.6. Operational Paranoia: The Cryptographic Search Bunker

We know that as a senior engineer, you trust code and architecture — not marketing promises. If you assume (rightfully) that any modern CLI tool is extracting telemetry in the background or sending your proprietary code to a remote server for processing, this section is for you. We designed AUM-IC's matching mechanism under a strict **Operational Paranoia** standard.

**How does AUM-IC find the exact relationship between your class and the CSS without compromising your machine?**

```
  Your .tsx / .astro / .vue file
           │
           │  [Babel/Cheerio AST — STATIC READ]
           │  Your code is NEVER executed.
           ▼
  Extracted class list
  [ "bg-white", "p-4", "hover:shadow-lg", "w-[320px]" ]
           │
           │  [Mathematical deduplication in RAM]
           ▼
  Unique combinations (only these are processed)
           │
           ├──────────────────────────────────────────┐
           │ Static class?                            │ Dynamic class?
           ▼                                          ▼
  ┌─────────────────────┐              ┌──────────────────────────┐
  │  L1: DuckDB         │              │  L2: Local JIT           │
  │  aumic-lexicon.duckdb│              │  tailwindcss from your   │
  │  READ-ONLY · Offline│              │  node_modules            │
  │  O(1) instant       │              │  Isolated · No network   │
  └──────────┬──────────┘              └─────────────┬────────────┘
             └─────────────────────────────────────────┘
                                  │
                                  │  [Everything happens in RAM]
                                  │  Your code NEVER leaves your machine.
                                  ▼
                        Pure CSS + aumic-lock.json
                        Memory destroyed upon completion.
```

1. **Total Isolation (Air-Gapped):** The `aumic-lexicon.duckdb` database is downloaded once and operates 100% locally, disconnected and immutable (Read-Only). It never pings any server. Zero shadow API calls. Zero tracking.
2. **Static Analysis (Zero Code Execution):** We never execute your scripts. We use AST interceptors (Babel) that read your components as a pure mathematical tree. We extract classes surgically, guaranteeing total immunity against arbitrary code execution attacks that could hide inside third-party projects.
3. **Deterministic Indexed Lookup:** Once a class is extracted (e.g. `bg-red-500`), the engine performs no dubious heuristics. It executes an exact in-memory vector query: `SELECT css_value FROM lexicon WHERE class_name = 'bg-red-500'`. If the utility exists in the 26,000+ class static dictionary, its CSS equivalent is injected instantly. If it's dynamic (e.g. `w-[320px]`), it's isolated and compiled in a closed local environment.
4. **Ephemeral Memory (Zero-Trace):** The entire matching and obfuscation process occurs exclusively in your processor's RAM. After injecting the final CSS file and saving `aumic-lock.json`, memory is destroyed. Your intellectual property never leaves your local ecosystem.

## 2. Non-Negotiable Design Principles

Every contribution, modification or extension of AUM-IC Tailwind Killer must respect these foundational principles. They are the backbone of the standard:

| # | Principle | Description |
| :---: | :--- | :--- |
| **P1** | **Absolute Determinism** | The same input always produces exactly the same output. No randomness, no timestamps in hashes. |
| **P2** | **Zero-Execution** | AUM-IC never executes user code. It only reads it as a syntax tree. No exceptions. |
| **P3** | **Offline-First** | The processing core requires no internet connection. AI is an optional layer, not structural. |
| **P4** | **Guaranteed Rollback** | Any destructive mutation must be reversible in a single command using `aumic-lock.json`. |
| **P5** | **Zero Framework Dependencies** | Output CSS must not require any preprocessor, runtime or framework to function. Pure standard CSS only. |

## 4. Security & Privacy Guarantees

This tool was built to operate inside corporate environments where source code is highly sensitive intellectual property. Our technical guarantees:

- **Zero telemetry:** There is no mechanism for reporting usage, errors or metrics to external servers. The source code is 100% auditable.
- **Zero network dependencies at runtime:** Once installed, AUM-IC operates completely offline. The only internet connection occurs during the initial npm installation.
- **Source code never leaves your machine:** AST analysis, deduplication and hash generation happen in local Node.js processes that terminate immediately upon task completion.
- **Optional and Controlled AI:** Integration with AI APIs (Claude, Gemini, DeepSeek) is 100% optional and only sends *unique combination hashes* — never source code, variable names or business logic.

**Want to verify it yourself?** You can audit exactly what is included in the package before installing it:

```bash
# See all files included in the npm package
npx npm pack @ingcrea/aumic-tailwind-killer --dry-run

# Inspect source code directly for any network calls
git clone https://github.com/ingcrea/aumic-tailwind-killer
grep -r "fetch\|axios\|http\|https\|request" src/ --include="*.ts"
# Expected result: zero network calls in the processing core.
```
